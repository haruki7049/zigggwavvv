# Contributing Guide for `zigggwavvv`

Thank you for contributing to `zigggwavvv`! This document outlines the development guidelines, setup instructions, and code verification workflow for contributors.

______________________________________________________________________

## 1. Project Overview

`zigggwavvv` is a WAV file reader/writer library written in Zig `0.16.0`, built on top of [`riff_zig`](https://github.com/haruki7049/RIFF.zig).

______________________________________________________________________

## 2. Development Environment Setup

We manage the development environment with **Nix** (flakes), optionally combined with **direnv**.

### Prerequisites

- [Nix](https://nixos.org/download.html) with Flakes enabled
- [direnv](https://direnv.net/) (optional)

### Quick Start

```bash
# Clone the repository
git clone https://github.com/haruki7049/zigggwavvv.git
cd zigggwavvv

# Enter the development shell
nix develop

# Or, allow direnv to load it automatically
direnv allow
```

Inside the environment, the required tools (`zig`, `zls`, `nil`, `zon2nix`, etc.) are placed in your path. `treefmt` is available through `nix fmt` or `nix develop`-based workflows configured by `treefmt-nix`.

You can also use any other way to install Zig, as long as the version matches.

### Zig version

This project uses `Zig 0.16.0` (see `minimum_zig_version` in `build.zig.zon`).

______________________________________________________________________

## 3. Repository Structure

- `src/root.zig`: Library entry point (public API and unit tests).
- `src/assets/`: Sample WAV files used by tests.
- `build.zig` & `build.zig.zon`: Build definition and package metadata.
- `.deps.nix`: Nix dependency lockfile generated by `zon2nix`. Regenerate it whenever `build.zig.zon` dependencies change.
- `.github/workflows/`: CI, Nix checks, API docs deployment, and stale issue handling.
- `AGENTS.md` & `.agents/skills/`: Guidelines and runbooks for AI agents.

______________________________________________________________________

## 4. Mandatory Verification Workflow

Before creating a Pull Request, you **MUST** run all verification commands and ensure clean execution:

| Command | Purpose |
| :--- | :--- |
| `treefmt` | Formats all files across Zig, Nix, GitHub Actions, and Markdown |
| `treefmt --fail-on-change` | Checks formatting compliance across all project files |
| `zig build` | Compiles and installs the static library |
| `zig build test` | Executes the unit tests |
| `zig build docs` | Emits API documentation (when the public API or doc comments change) |

______________________________________________________________________

## 5. Updating Dependencies

When changing dependencies in `build.zig.zon`, regenerate the Nix lockfile so the Nix build stays in sync:

```bash
zon2nix > .deps.nix
treefmt
```

To update Nix inputs, run `nix flake update`.

______________________________________________________________________

## 6. Pull Request Guidelines

1. **Format & Test Verification**: Ensure `treefmt --fail-on-change`, `zig build`, and `zig build test` all pass cleanly.
1. **Conventional Commits**: Use conventional commit prefixes (`feat:`, `fix:`, `docs:`, `refactor:`, `build:`, `test:`, `ci:`), optionally with a scope such as `build(flake.lock):`.
1. **PR Description**: Include a clear summary of changes, an explicit issue-closing keyword (e.g., `Closes #123`), and confirmation of completed verification commands.
1. **English Only**: Write commit messages, PR titles, PR descriptions, code comments, and documentation in English.
